# GlowBeauty — кросплатформний застосунок

**GlowBeauty** — навчальний застосунок для ведення списку декоративної косметики. Він дозволяє додавати товари, переглядати список, здійснювати пошук, сортувати та видаляти записи зі збереженням даних між запусками.

Головна особливість проєкту — повторне використання спільної бізнес-логіки у веб- та десктопному клієнтах.

## Технологічний стек і компетентності

Під час розробки GlowBeauty було опрацьовано декілька напрямів програмування: створення веб- і мобільних інтерфейсів (**frontend**), розробка REST та GraphQL API (**backend**), побудова десктопних застосунків на Electron (**desktop**), а також проєктування спільного ядра та платформних адаптерів (**software architecture**).

Основний акцент портфоліо зроблено на **кросплатформній архітектурі та повторному використанні програмного коду**. Саме ці рішення дозволяють забезпечити однакову бізнес-логіку на різних платформах.

## Ключові результати проєкту

### 1. Повторне використання бізнес-логіки

У пакеті [@glowbeauty/core](packages/core) створено сервіс [ProductsService](packages/core/productsService.js), який реалізує додавання, видалення, пошук, сортування та перевірку косметичних товарів.

Спільний сервіс використовується веб- та десктопним клієнтами, що дозволяє уникати дублювання бізнес-логіки.

### 2. Платформні адаптери

Реалізовано два окремі механізми збереження даних:

- [LocalStorageAdapter](packages/web/localStorageAdapter.js) — для роботи з браузерним localStorage;
- [FileStorageAdapter](packages/desktop/fileStorageAdapter.js) — для збереження інформації у локальному JSON-файлі.

Використання адаптерів дозволяє відокремити бізнес-логіку від способу зберігання даних.

### 3. Десктопний застосунок на Electron

Створено десктопну версію GlowBeauty з використанням Electron. Взаємодія між головним процесом та інтерфейсом організована за допомогою IPC.

Основні компоненти реалізації:

- [main.js](packages/desktop/main.js) — головний процес Electron;
- [preload.cjs](packages/desktop/preload.cjs) — надання доступу до дозволених функцій;
- [ipcHandlers.js](packages/desktop/ipcHandlers.js) — обробка IPC-запитів.

Це дозволяє працювати з локальними файлами через визначений інтерфейс взаємодії.

### 4. Автоматизоване тестування

Для перевірки роботи компонентів застосунку використано вбудовані засоби тестування Node.js.

Тести охоплюють:

- [спільне ядро](packages/core/test);
- [вебклієнт](packages/web/test);
- [десктопний клієнт](packages/desktop/test).

Під час виконання лабораторної роботи №7–8 було успішно виконано **33 автоматичні тести**.

## Структура монорепозиторію

```text
lab_7-8/
├── packages/
│   ├── core/          # Спільна бізнес-логіка
│   ├── web/           # Вебклієнт
│   └── desktop/       # Десктопний клієнт Electron
```

Монорепозиторій організовано за допомогою npm workspaces. Пакети `web` і `desktop` використовують спільну бізнес-логіку пакета `core`, але мають власні інтерфейси та способи збереження даних.

## Запуск проєкту

Для запуску потрібні встановлені Node.js та npm.

**1. Встановлення залежностей**

Перейдіть до папки `lab_7-8` та виконайте:

```bash
npm install
```

**2. Запуск вебклієнта**

```bash
npm run start:web
```

Після запуску вебклієнт буде доступний за адресою:

http://localhost:3000

**3. Запуск десктопного застосунку**

```bash
npm run start:desktop
```

**4. Запуск автоматичних тестів**

```bash
npm test
```
